# Shared garment adoption

This adapter consumes MaleModBase through `dependencies/base.lock.json` and
`tools/Resolve-Base.ps1`. `build.cmd` rejects a wrong commit, missing APIs and
tracked/untracked changes to shared runtime inputs. Fresh development checkouts
can clone the pinned dependency into ignored `dependencies/MaleModBase`; an
existing checkout is never reset or overwritten. `MALEMOD_BASE_PATH` selects an
explicit checkout. `build.cmd --diagnostic` is the visible opt-in for testing an
uncommitted shared candidate. It is not a production dependency bypass.

The menu uses shared control vocabulary and a Clothing row with Naked/Jockstrap.
Naked is the initial default, and `WolverineLive.ini` stores `Clothing/Style`
without changing existing preferences. F6 and arrow/Shift controls are retained;
title-only View Switch/Idle Video remain after the new Clothing row.

## Source surfaces and original donors

`jockstrap_measured_data.h` retains measured original-edge waistband donors from
both complete native body resources, the 13 actual final unified attachment
edge donors, and measured under-glute paths. The recipe uses the observed source
body +X forward/+Y lateral/+Z up axes, not shaft pitch. It was generated by
Base `tools/prepare_garment_source.py`; source hashes and the exact character
recipe are tracked in Base `assets/garments/wolverine-jockstrap-donors.json`.

The adapter reads the actual final displayed `nrPacked`/`nrIndices` surface
(17,528 vertices/35,000 triangles), not the earlier rounded `rsPacked` surface.
It submits after final unified collar application. All cloth positions, UVs,
lighting, mesh/material slots and bounded support laws come from Base.

`Generate-GarmentSupport.py` follows exact final nr->rs->r14->original cage
lineage and the actual shaft/scrotum membership fields. The generated support
groups preserve the two original source lobes (negative/positive Y); they are
not inferred game bone names. `AggregateNumericalSupport` maps measured contacts
into bounded source accelerations, injected immediately after the original
common gait/gravity acceleration and before drag/position integration. Naked,
reset and character replacement disable the branch. The original solver,
morph mappings, geometry and clinical clock arithmetic remain authoritative.

## Threading, pose and rendering

CPU contact/fabric generation runs in `JockstrapCpuWorker` with one latest
immutable request and one published immutable output. Epoch/generation guards
reject a completed job after Naked/reset/replacement. Render and source physics
read a coherent snapshot, without waiting for the cloth solve. Shader creation,
actual body/anatomy bone-palette capture, CPU skinning and D3D9 draw/restoration
remain sequential on the native render thread. Reset and scene release stop the
worker and free GPU objects outside the Windows DLL loader lock.

Every garment vertex carries normalized source donors. The draw adapter blends
**all actual native skin influences** of those donors, including each body
section's measured gameplay bone-remap table. The waistband is not posed using
one pelvis matrix. Palettes must match the present render-frame serial; missing
palettes skip a draw rather than mixing old poses. Body skin indices/weights
come from durable original CPU arrays, never an unlocked D3D buffer pointer.
The small procedural cloth shader compiles actual VS3/PS3 bytecode, preserves
four material slots, uses depth/opaque two-sided cloth and restores D3DSBT_ALL.
The local cloth silhouette uses the latest completed CPU solve, then current
frame native palettes transport it with the character. This avoids actor-pose
lag; fast local anatomy changes may remain one cloth solve behind. Native shadow
integration and installed garment appearance are separate gates.
